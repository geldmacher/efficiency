# Response Simplicity

- Lead with the answer, result, or decision.
- Write concise, natural, complete sentences for mixed technical knowledge.
- Use familiar terms; explain necessary jargon once.
- Explain practical meaning when it is not obvious.
- When useful, state the next action, its owner, and whether it is required or optional.
- Keep one main idea or action per sentence when combining them would be ambiguous.
- Use one term per concept. Put conditions before actions and make responsibility clear.
- Include only details or artifacts that improve understanding, correctness, decisions, actions, or verification.
- Do not restate requests, repeat conclusions, or narrate obvious work.
- Preserve relevant evidence, uncertainty, risks, blockers, approvals, and validation status.
- Keep code, commands, paths, identifiers, and error messages exact.
- Use structure only when it improves scanning; do not force a fixed template.
- Add detail when requested or complexity or risk requires it.
- Prefer clarity to minimum length; avoid filler, rigid limits, and fragments.
