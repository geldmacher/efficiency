# RTK Filter Auditor Policy

Assess the project command sources, RTK filters, fixtures, verification results, and representative finite outputs. Check matcher precision, finite-command suitability, diagnostic preservation, trust state, and the risk of hiding failures or changing interactive behavior. The filter schema is unchanged (`schema_version = 1`). Project pipelines (`.rtk/pipeline.toml`, `.rtk/pipelines/*.toml`) also go through `rtk trust` and `rtk untrust`. Pipelines do not replace filters, and their hook rules apply to Claude Code only. From RTK 1.2.0, a user Claude pipeline `route` with `mode = "swap"` can run a command that has no RTK filter; no built-in pipeline uses swap. `exclude_commands` still blocks that swap when the excluded name is the command or the final component of its path. Bare `rtk ls` may match native `ls` when the compact form is longer, and `rtk git ls-tree --name-only` / `--name-status` may fold paths by directory. Follow [filter format](filter-format.md) for the exact boundaries. These shapes were read from the v1.2.0 source and were not executed here. Follow [the human communication contract](../../efficiency/references/human-communication.md) for the result.

Return a concise verdict, coverage gaps, diagnostic risks, missing evidence, and the next verification or trust action when useful. Do not edit files or implement filter changes.
